# Editor toolbar and embed tools

Status: in progress. Feature document for the editor improvements requested after the sidebar drag&drop and
title/placeholder fixes. Subagents read this file in order and stop before `## Log`.

## Specs

**S1 — Undo and redo in the app header.** The user's words: "y el undo y redo" and "el undo redo en el header/nav
donde esta el Search y el boton de ligh mode". A rule: the app canvas toolbar end (`.canvas-toolbar-end`, which
holds `SearchPalette` and `ThemeToggle` in `web/src/components/layout/app-shell.tsx`) gains Undo and Redo buttons;
each one is enabled only while the page editor that is currently mounted can undo or redo, and both are inert
(disabled, not rendered as clickable) on routes with no page editor (`/` and `/trash`). Clicking pauses nothing:
it performs the same history step the keyboard shortcut would.

**S2 — Insert link.** The user's words: "quiero el de agregar link y link embed", clarified with "Es solo el embed
de YouTube y X", so "link embed" adds no work beyond S4 and S5. A rule: applying, editing and removing a link on a
text selection keeps working from the editor's existing bubble menu (`Link` with "Paste a link...", vendored at
`web/src/components/block-editor/bubble-menu/link-selector.tsx`); the slash menu must NOT gain a link item, because
a slash item replaces its trigger range while a link is a mark applied to a selection. This spec is satisfied only
when the flow is observed in a real browser, not only in jsdom.

**S3 — Insert star.** The user's words: "el insert star", clarified with "Es el ⭐: insertar el carácter". A rule:
the slash menu gains one item that inserts the ⭐ character at the cursor. No new node, no new dependency, and the
inserted character must survive save and reload as ordinary text.

**S4 — YouTube embed.** The user's words: "embed YouTube" together with "los podemos agregar en el slash?". A rule:
the slash menu gains an item that turns a YouTube reference into a block — `youtube.com/watch?v=`, `youtu.be/`,
`youtube.com/shorts/`, `youtube.com/embed/`, `youtube.com/live/` and a bare 11-character id must all resolve to the
same video — and the block renders a 16:9 `youtube-nocookie.com/embed/<id>` iframe. The block must round-trip
through the page content JSON (save, reload, still one embed) and must never render an iframe for input it cannot
parse: unparseable input degrades to a plain link.

**S5 — X/Twitter embed.** The user's words: "embed X/Twitter". A rule: the slash menu gains an item that turns a
tweet URL (`x.com`, `twitter.com`, with or without query string) or a numeric id into a block. The third-party
widget script (`platform.twitter.com/widgets.js`) is loaded lazily, never from the page frame, and with a timeout;
when the script is unavailable, blocked or slow, or the id cannot be parsed, the block degrades to a plain link to
the tweet. No crash, no infinite spinner, and the degraded state must be reachable in a test without network access.
Upstream interactive resize handles are out of scope for S4 and S5 (see L4).
